# What Adobe Commerce supports today

Checkout Fields only uses documented, out-of-process Adobe Commerce features. This page lists each one, with its source, and what still has to be confirmed on a live Adobe Commerce as a Cloud Service instance. The app hasn't been installed on one yet; everything below the line "To confirm" is handled defensively in the code, and listed here so you can check it before going live.

## What the app relies on

| Feature | Used for | Source |
|---|---|---|
| Cart custom attributes: `setCustomAttributesOnCart` | The storefront saves the values on the cart. Commerce copies cart custom attributes to the order when it is placed. | [GraphQL: set custom attributes on a cart](https://developer.adobe.com/commerce/webapi/graphql/schema/attributes/mutations/set-custom-cart) |
| Order custom attributes in REST | The order grid and order view read the values. | [REST: custom attributes](https://developer.adobe.com/commerce/webapi/rest/modules/custom-attributes) |
| Webhook `observer.sales_order_place_before`, with `exception` responses | The server-side check that stops an order with missing or invalid values. | [Order placement validation](https://developer.adobe.com/commerce/extensibility/webhooks/use-cases/order-placement-validation), [Order custom attributes validation](https://developer.adobe.com/commerce/extensibility/webhooks/use-cases/order-custom-attributes-validation) |
| Webhook signatures | Rejecting requests that didn't come from Commerce. | [Signature verification](https://developer.adobe.com/commerce/extensibility/webhooks/signature-verification) |
| Webhooks registered by App Management | Installing the webhook with the app, no Admin setup. | [App Management: webhooks](https://developer.adobe.com/commerce/extensibility/app-management/installation/webhooks) |
| Admin UI SDK: menu, order grid column, order view button | The Admin pages. | [App Management: Admin UI SDK](https://developer.adobe.com/commerce/extensibility/app-management/installation/admin-ui-sdk), [Order extension points](https://developer.adobe.com/commerce/extensibility/admin-ui-sdk/extension-points/order/) |

On PaaS, cart and order custom attributes need the `magento/out-of-process-custom-attributes` module; on Adobe Commerce as a Cloud Service they are built in.

## To confirm on a live instance

| Question | What the code does meanwhile | How to check |
|---|---|---|
| The exact shape of the order's custom attributes in the `observer.sales_order_place_before` payload (`custom_attributes_serializable` as a JSON string, a list or a map) | `parseCustomAttributes` accepts a JSON string, a list of `{ attribute_code, value }` (or `code`) and a plain map, and also reads `extension_attributes.custom_attributes`. | Place an order and read the request in the Commerce webhook logs (**System → Webhook Logs**), or log `params.__ow_body` temporarily in `validate-order`. |
| Whether `observer.sales_order_place_before` is on the instance's supported webhook list | — | **System → Webhooks** after installing, or the webhooks `supportedList` REST call. If it isn't, use `plugin.magento.quote.api.cart_management.place_order` instead and adjust the field paths. |
| Whether the order grid sends entity IDs or increment IDs | `findOrders` searches both and answers under the ID that matched. | `aio app logs` for `order-grid`. |
| The order view button `path` format for the app's `/order` route | `#/order`, with the order ID read from the button context. | Click the button on an order. |
| The Admin order view's **Custom Attributes** tab | Not relied on: the app's own order page and grid column show the values. | Open an order. Edits made there skip this app's validation (see the roadmap). |
| Whether order email templates can print order custom attributes | Not relied on. `describeValues(fields, values, { emailOnly: true })` gives the rows for an email, so an app-sent email or an order comment is the fallback. | [Email templates](https://developer.adobe.com/commerce/frontend-core/guide/templates/email): try `{{var order.getData('custom_attributes')}}` in a test template. |
| The GraphQL type for `custom_attributes` on `setCustomAttributesOnCart` | The kit inlines the values as JSON-escaped strings with only `$cartId` as a variable, so it doesn't depend on the input type's name. | [GraphQL types](https://developer.adobe.com/commerce/webapi/_includes/autogenerated/graphql-api-saas-types-c-e). |
| Reading a signed-in shopper's customer group in GraphQL | Without it, group-limited fields are shown to everyone and the webhook applies the real group. | Try `customer { group { uid } }` on the instance, see the [storefront guide](../storefront/README.md#customer-groups). |
| Admin UI SDK version on the instance | `app.commerce.config.ts` uses the order `gridColumns` and `viewButtons` extension points. | [Admin UI SDK release notes](https://developer.adobe.com/commerce/extensibility/admin-ui-sdk/release-notes/). |
